# Android push через Firebase Cloud Messaging

## Что подготовлено

Android `0.7.5` получает родительские уведомления через FCM data messages с высоким приоритетом. Обработчик работает без открытия WebView: проверяет устройство, сервер, роль и версию настроек, затем показывает обычное Android-уведомление. Название препарата и дозировка в push не передаются. Родительские сообщения не отправляются детским профилям; детский будильник остаётся локальным.

Сервер отправляет push после отметки ребёнка и проверяет отсутствие отметок каждые 10 секунд. У каждого устройства отдельная регистрация и журнал доставок. Временные ошибки повторяются, недействительный FCM-токен удаляется. При отключении уведомлений или отзыве доступа новые отправки прекращаются. Повторное включение не воспроизводит сообщения за время добровольного отключения. В базе JSON/PostgreSQL FCM-токены являются секретными данными; обычные API списков устройств их не возвращают.

Резервная проверка через WorkManager сохраняется. При запрете уведомлений она не сдвигает курсор мимо недоставленных сообщений. Подтверждения доступны для восстановления за последние 24 часа, напоминания — пока действует их окно. Первый курсор устанавливается в момент подключения, а не после получения первого ответа сервера.

## Что требуется от Firebase

1. Создайте Firebase-проект в своём Google-аккаунте или используйте существующий. Добавьте Android-приложение с package name **`org.epiapp.android`**. Для FCM не требуется добавлять Analytics.
2. Скачайте `google-services.json` из настроек Android-приложения. Это конфигурация клиента, а не приватный ключ service account. В GitHub репозитории добавьте его полное содержимое в Actions secret **`ANDROID_GOOGLE_SERVICES_JSON`**. Локальная сборка читает `android/app/google-services.json` (исключён из Git).
3. В Google Cloud включите Firebase Cloud Messaging API (HTTP v1). Создайте service account с ролью Firebase Cloud Messaging API Admin (`roles/firebasecloudmessaging.admin`, включает `cloudmessaging.messages.create`) и выдайте JSON-ключ для сервера. Используйте минимальные права на нужный проект.
4. Содержимое приватного JSON-ключа добавьте **только в Northflank runtime secret `FIREBASE_SERVICE_ACCOUNT_JSON`**, привязанный к сервису. Не отправляйте приватный ключ в чат и не коммитьте его. Android-конфигурация и серверный service account должны относиться к одному проекту.
5. Перезапустите сервис Northflank. Для отправки нужны исходящие HTTPS-соединения к `oauth2.googleapis.com` и `fcm.googleapis.com`.
6. Запустите GitHub workflow **Android debug prerelease** на `web-next`. Он проверит package name, соберёт APK и запустит Android-тесты. Без клиентской конфигурации сборка тестируется, но новый пререлиз не публикуется. CI отдельно компилирует вариант с синтетической конфигурацией; этот APK никогда не публикуется.
7. После публикации `v0.7.5-debug` укажите его APK в Northflank `ANDROID_APK_URL` и перезапустите сервис, чтобы бот выдавал push-версию. До этого бот продолжает выдавать `0.7.4-debug`.
8. Установите APK на родительские телефоны, при необходимости повторно подключите их через бота и разрешите уведомления Android. В приложении откройте **Уведомления → Настройки**: должно отображаться «Устройство зарегистрировано для push».

## Проверка на телефонах

На каждом родительском телефоне закройте экран приложения, заблокируйте телефон, затем подтвердите тестовый приём из детского профиля. Проверьте уведомление, отсутствие дубля после открытия кабинета, отключение/включение уведомлений, отзыв устройства и напоминание при отсутствии отметки. Такие проверки требуют реальных устройств и настроенного Firebase; тесты с заглушками их не заменяют.

FCM не гарантирует доставку при отсутствии сети, принудительной остановке приложения через настройки Android, запрете уведомлений или ограничениях Google Play services. Высокий приоритет предназначен для сообщений, которые показывают пользователю уведомление. Повторное подключение Firebase не заменяет разрешений Android.
