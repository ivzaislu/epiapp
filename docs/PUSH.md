# Эксперимент UnifiedPush/VAPID

Ветка **`unifiedpush-vapid`**, база — `web-next` на коммите `11eaf48639e77c844daac3afb41074eed7bca3bf`.

## Назначение

Проверить модель «свой бэкенд + один готовый APK» без Firebase-проекта, `google-services.json`, service account и нашего общего push-шлюза. В APK включены UnifiedPush connector и embedded FCM distributor. Бэкенд отправляет стандартный Web Push с VAPID и шифрованием `aes128gcm` непосредственно на адрес, полученный приложением через Google Play services. Это всё ещё инфраструктура Google; отдельные аккаунты и ключи Firebase не требуются.

Это прототип, а не подтверждённая гарантия доставки на всех Android. Google-регистрация в embedded distributor использует менее документированный механизм, чем официальный Firebase SDK. Работу на физических телефонах с закрытым приложением нужно проверить отдельно.

## Что делает бэкенд

- Автоматически создаёт пару VAPID-ключей при первом запуске с настроенным публичным HTTPS-адресом; ключи сохраняются в той же JSON-базе или PostgreSQL, что и остальные данные. Несколько процессов не создают разные ключи. При перезапуске ключи не меняются.
- Выдаёт публичный ключ авторизованному родительскому устройству через `GET /api/device/push/key`. Приватный ключ и подписки не возвращаются обычными API списков устройств.
- Принимает подписку через `POST /api/device/push`, привязывая её к подключённому устройству, серверу, версии настроек и ключу VAPID.
- В этой версии разрешены только Google endpoints `https://fcm.googleapis.com/fcm/send/...` и `/wp/...`; произвольные URL отвергаются. Поддержка внешних доставщиков в этом эксперименте не заявляется.
- Отправляет уведомления каждому устройству родителя/администратора. Детскому профилю родительские сообщения не отправляются. Название препарата и дозировка в payload не включаются.
- Повторяет временные ошибки, удаляет недействительные подписки, прекращает новые отправки отозванным устройствам и при отключении уведомлений. Журнал доставок и клиентская дедупликация защищают от повторных уведомлений.

Для push не добавляются новые секреты в ENV. Сохранность базы важна: VAPID-ключи и подписки должны переживать перезапуск контейнера. Серверу требуется исходящий HTTPS-доступ к `fcm.googleapis.com`. Используется уже настроенный `APP_BASE_URL` или `NF_HOSTS`.

## Изолированная проверка

1. Разверните **отдельный тестовый бэкенд из `unifiedpush-vapid`** с собственной базой и тестовым Telegram-ботом. Не запускайте два long-polling процесса для одного Telegram-бота. Для Northflank выберите эту ветку при создании тестового сервиса; настройки домена и PostgreSQL описаны в [NORTHFLANK.md](NORTHFLANK.md).
2. Для Docker: скопируйте `.env.example` в `.env`, заполните Telegram-бота, администратора, `APP_BASE_URL` и `APP_DOMAIN`, затем выполните `docker compose up -d --build`. Никаких Firebase-полей заполнять не нужно.
3. Установите APK **EpiApp UP** из пререлиза `v0.7.5-up.1`. Package name: `org.epiapp.android.unifiedpush`; он устанавливается рядом с обычным EpiApp. Схема подключения — `epiapp-up://connect`, чтобы тестовая ссылка не открыла основное приложение.
4. Отправьте `/start` тестовому боту, подключитесь через «Подключить Android» и разрешите уведомления Android. В родительском кабинете откройте **Уведомления → Настройки** и дождитесь статуса регистрации UnifiedPush/VAPID.
5. Нажмите **«Тест доставки через 30 секунд»**, сверните приложение и заблокируйте телефон. Это сообщение доставляется только push-путём: оно отсутствует в резервной ленте и не создаёт отметку приёма. При доступной сети проверьте, что сообщение пришло без открытия приложения.
6. Дополнительно проверьте подтверждение из детского тестового профиля, напоминание при отсутствии отметки, два родительских телефона, отсутствие дубля после открытия кабинета, отключение уведомлений и отзыв устройства.

Обычный APK `0.7.4` не поддерживает этот эксперимент. EpiApp UP требует API из этой ветки; подключение к старому бэкенду покажет ошибку регистрации и оставит резервную проверку. Внутри APK сохранены локальный детский будильник и резервные проверки WorkManager. Принудительная остановка приложения через настройки Android, отсутствие сети и запрет уведомлений остаются ограничениями доставки.

## Автоматические проверки

`npm test` заменяет Telegram заглушкой и запрещает неожиданные внешние fetch-запросы. Тесты Web Push используют криптографию на настоящих тестовых ключах: создают запрос VAPID, проверяют подпись и расшифровывают payload без отправки в Google. CI проверяет Node.js, PostgreSQL, Docker, Android/Robolectric и собирает экспериментальный APK. Автоматические тесты не подтверждают реальную доставку Google на телефон.
