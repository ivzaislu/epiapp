# EpiApp Android APK

Ветка `epiappapk` добавляет один Android APK для ребёнка, родителей и администратора поверх существующего EpiApp-сервера.

Приложение **не назначает лечение и не подтверждает фактический приём лекарства**. Оно показывает схему, которую внесли родители, запускает напоминания и сохраняет отметку пользователя.

## Архитектура

APK использует существующий защищённый веб-интерфейс EpiApp в Android WebView, поэтому таблетница, роли, графики и статистика остаются общей серверной логикой.

Нативная Android-часть отвечает за:

- безопасное подключение устройства;
- локальное хранение device-token через Android Keystore;
- точные Android alarms;
- полноэкранную срочную тревогу;
- звук и вибрацию до явного выключения экрана тревоги;
- восстановление расписания после перезагрузки/смены времени;
- фоновую синхронизацию расписания примерно раз в 30 минут;
- отмену оставшихся тревог после подтверждённой сервером отметки.

## Подключение устройства

Сначала Telegram-аккаунт должен уже иметь доступ к семье EpiApp: `admin` задаётся через `TELEGRAM_ADMIN_ID`, ребёнок и второй родитель получают доступ через обычные Telegram-приглашения.

После этого пользователь нажимает в личном чате с ботом:

```text
📲 Подключить Android
```

Бот выдаёт одноразовый шестизначный код, например:

```text
123 456
```

Код действует 5 минут и используется один раз. APK отправляет его на `/api/device/pair` и получает случайный 256-битный device-token. На сервере сохраняется только SHA-256 hash device-token; на Android сам token шифруется ключом из Android Keystore.

Telegram bot token, `TELEGRAM_ADMIN_ID` и серверные секреты в APK не встраиваются.

## Роли

Один и тот же APK работает для всей семьи:

- `child` — открывается детский экран, активируются локальные alarms;
- `parent` — открывается родительский кабинет, графики и настройки; локальный детский alarm не включается;
- `admin` — открывается родительский кабинет с административными возможностями.

При отзыве пользователя через Telegram его связанные Android-устройства тоже становятся недействительными. Сервер повторно проверяет текущую роль при native session/schedule запросах.

## Будильники

При стандартных настройках сервера:

- +15 минут после заданного времени — обычное Android-уведомление;
- +30 минут — полноэкранная срочная тревога;
- +45 минут — повторная срочная тревога;
- +60 минут — ещё одна срочная тревога.

Интервалы берутся из родительских настроек EpiApp и не зашиты навсегда в APK.

Экран срочной тревоги воспроизводит системный alarm sound в цикле и вибрацию, пока пользователь не нажмёт одну из видимых кнопок:

- `💊 Открыть EpiApp`;
- `🔕 Выключить будильник`.

**Выключение будильника не создаёт отметку о приёме.** Отметка появляется только после отдельного подтверждения в EpiApp и успешного ответа сервера.

Если отметка уже существует, оставшиеся тревоги этого слота отменяются и планируется следующий день.

## Android-разрешения

Для максимальной надёжности ребёнок должен разрешить приложению:

- Notifications;
- exact alarms / Alarms & reminders;
- full-screen alarm access, если Android показывает такую настройку.

APK запрашивает/открывает системные экраны этих разрешений на поддерживаемых версиях Android.

Если exact-alarm permission запрещён, приложение использует менее точный Android alarm как fallback. Если full-screen permission запрещён, срочное высокоприоритетное уведомление остаётся, но система может не открыть полноэкранный экран автоматически.

Ни Android, ни EpiApp не могут абсолютно гарантировать слышимый звук при любых пользовательских/производительских настройках телефона: пользователь может отключить уведомления, alarm channel, звук, включить специальные режимы DND или производитель может ограничить фоновые процессы. Поэтому Telegram-эскалация родителям остаётся вторым независимым каналом.

## Работа без сети

После успешной синхронизации детский APK хранит локальную копию времени и интервалов. Уже поставленные Android alarms могут сработать без интернет-соединения.

Отметка о приёме и обновление серверной статистики требуют связи с EpiApp-сервером. После восстановления сети приложение снова синхронизирует расписание.

После `BOOT_COMPLETED`, обновления APK, смены времени или часового пояса локальное расписание восстанавливается из кэша и затем сверяется с сервером.

## Сборка debug APK

Нужны JDK 17, Android SDK 35 и Gradle 8.9.

```bash
gradle --no-daemon :androidApp:assembleDebug
```

Результат:

```text
androidApp/build/outputs/apk/debug/androidApp-debug.apk
```

GitHub Actions ветки `epiappapk` выполняет эту сборку автоматически и публикует artifact `epiapp-debug-apk`.

Debug APK подписывается стандартным debug-ключом и подходит для семейного тестирования/sideload. Для постоянного release APK нужен отдельный release keystore; приватный keystore и его пароли нельзя хранить в репозитории.

## Сервер

APK требует серверный код именно из `epiappapk`, потому что используются дополнительные endpoints:

```text
POST /api/device/pair
POST /api/device/session
GET  /api/device/schedule
```

Production ENV остаётся прежним; отдельный секрет для APK не требуется:

```dotenv
TELEGRAM_BOT_TOKEN=...
TELEGRAM_ADMIN_ID=...
APP_BASE_URL=https://epiapp.duckdns.org
HOST=127.0.0.1
PORT=3000
DATA_FILE=/var/lib/epiapp/epiapp.json
```

Node.js по-прежнему должен слушать только `127.0.0.1`; наружу EpiApp публикуется через Nginx/HTTPS.
